# learning-path

A Claude Code skill that takes you through a technology (Java, Python, Docker, anything) from beginner to expert, one topic at a time. Progress is saved in plain files, so you can open Claude Code on any day and resume exactly where you stopped.

## How it works

Each topic follows the same six steps:

1. Roadmap: Claude builds a leveled topic list for the technology, checked against official sources, and saves it. It refreshes itself when it is more than 30 days old.
2. Learn: a short explanation with a small code example, then a 3 to 5 question quiz. The score is never a gate.
3. Brainstorm: Claude suggests 2 or 3 small project ideas (or you bring your own), writes a spec with acceptance criteria, and creates the topic folder with build setup only.
4. Build: you write the code. Claude waits, and can give a hint to get started.
5. Review: Claude builds and tests your code, then gives hints grouped by spec, topic use, quality and best practices. It never hands you the fix up front; you can ask to see the fix for one hint at a time.
6. Track: the topic is marked done (or done with an override if you skip a passing review) and progress is updated.

## Install

Link the skill so edits in this repo take effect immediately:

```bash
mkdir -p ~/.claude/skills
ln -s "$PWD/skill/learning-path" ~/.claude/skills/learning-path
```

Or copy it instead (note: the test runner refuses to run against a copy, see "Running the tests"):

```bash
mkdir -p ~/.claude/skills
cp -r skill/learning-path ~/.claude/skills/learning-path
```

Optional skills that make two steps better when installed: `learn` (teaches the Learn step; without it the skill teaches inline and says so once) and `engineering:code-review` (runs the Quality check of the review; without it the skill runs its own checklist and says so once).

## Commands

| Command | What it does |
|---|---|
| `/learning-path <technology>` | Start a new roadmap, or continue an existing one |
| `/learning-path` | Continue the most recently active roadmap |
| `/learning-path refresh` | Refresh the current roadmap now |
| `/learning-path status` | Show the roadmap and progress |

## Your `learning/` folder

The first time, Claude asks where to put your workspace: `Here` creates a new `learning/` folder in the current folder (the default), or `Somewhere else` uses a path you give. The answer is saved as one line (the absolute path of the `learning/` folder) in `~/.claude/learning-path-workspace.txt`, so later sessions find it from any folder. A `learning/` folder in the current folder always wins. Set the environment variable `LEARNING_PATH_CONFIG` to use a different config file.

```
learning/
  index.md              all roadmaps: progress, current topic, last active
  java/
    roadmap.md          topics, levels, status and stage (single source of truth)
    specs/
      03-collections.md
    code/
      03-collections/   build setup only (pom.xml, empty src folders); you write the code
```

One folder per technology, so switching never touches another roadmap. From the Build menu, `Something else` lets you pick another topic or switch roadmap; the topic you leave stays in progress (`[~]`) with its stage, so you can come back to it. Claude never overwrites your files, and an existing topic folder is reused as is. `index.md` is a summary and can be rebuilt from the roadmap folders.

## About roadmap.sh

Roadmaps are generated by Claude, not copied. roadmap.sh is linked for you to view personally only; its content is never copied or scraped.

## Running the tests

Prerequisites: the `claude` CLI (logged in), and Java (JDK with `javac`) and Maven. No scenario runs Python code, so Python and pytest are not needed.

```bash
bash tests/run-all.sh --repeat 2
```

Each scenario in `tests/scenarios/` makes real `claude -p` calls, so a full run takes a long time. Run one scenario with `bash tests/run-scenario.sh tests/scenarios/<dir>`. Fixture dates use a `__TODAY__` token that the runner replaces with the current date. After editing `tests/scenarios/_shared/`, regenerate the review fixtures with `bash tests/scenarios/_shared/make-fixtures.sh`.

What the runner does to your machine:

- **Skill symlink.** It needs `~/.claude/skills/learning-path` to be a symlink to this checkout's `skill/learning-path`. If the entry is absent it creates that symlink (and `~/.claude/skills`) and leaves it in place. If the entry is a copy, a dangling symlink, or a symlink to another checkout, the scenario fails with a message telling you to move it aside.
- **Your Claude setup.** Scenarios run headless `claude -p` with your real Claude config, login, plugins and skills, so installed skills such as `learn` or `engineering:code-review` take part. They run with `--permission-mode acceptEdits` and allow `Bash Read Write Edit Glob Grep WebSearch WebFetch Skill` without asking, inside a fresh temp folder per scenario.
- **Workspace config.** The runner sets `LEARNING_PATH_CONFIG` to a file inside that temp folder, so tests never read or change your real `~/.claude/learning-path-workspace.txt`.

Online vs offline: with access to Maven Central, the review runs `mvn -q test` and reports the test result. Without it (as in some sandboxes), dependencies cannot be downloaded, so the review compiles with `javac` and says in one line that the tests could not be run. Scenario 05 accepts either, as long as the reply reports what happened. Scenario 21 runs `mvn -q validate` on the generated `pom.xml`.
